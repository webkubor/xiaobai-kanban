# 📝 怎么把需求讲清楚——写给 Agent 的「需求说明书」模板

> 这是「从零到上线」里第五步的展开。上一篇说**需求说不清 = 做错**，这一篇专攻这一件事：**怎么把一个想法，说成 Agent 一次就能做对的需求。**
>
> 你不需要懂任何技术。你只需要学会「把心里想的，按顺序说全」。

---

## 先记住一个残酷的事实

> **Agent 做的坏事，九成不是它笨，是你没把需求说清。**

它不会读心。你说「做个官网，好看点」，它能给你做出 100 种官网，但可能没一种是你想要的。不是它不行，是你把「决定权」全部推给了它——**你偷懒的地方，最后都要靠来回改去还债。**

需求说得越清楚，你后面越省事。这篇就是教你「一次说清」。

---

## 一个万能框架：四句话

```
背景 + 目标 + 范围 + 验收标准
```

### 逐句拆开

| 这一句 | 回答什么问题 | 少了它会怎样 |
|---|---|---|
| **背景** | 为什么要做这件事？给谁用？ | Agent 不知道往哪个方向使劲，做出来「能用但没用」 |
| **目标** | 做完之后长什么样？ | 不知道做成什么，Agent 只能猜 |
| **范围** | 这次做多少？**不做什么**？ | 它可能一口气把没要求的功能也做了，还做错 |
| **验收标准** | 怎么算「做完了」？ | 你觉得没做完，它觉得做完了，来回扯 |

> 「不做什么」和「做什么」一样重要。说清边界，Agent 才不会自作主张。

## 直接套的模板（填空就行）

每次给 Agent 派活，把下面四行填了：

```text
【背景】我想做一个 ______ ，给 ______ 用，因为 ______ 。
【目标】做完之后它应该能 ______ ，长这样：______ 。
【范围】这次只做 ______ ，先不做 ______ 。
【验收】我打开它，应该能看到 ______ ，点 ______ 应该 ______ ，手机上也要 ______ 。
```

### 一个真实例子

> 【背景】我想给公司做一个官网，给客户看产品，因为客户总问「你们是干嘛的」。
> 【目标】一个能打开的网站，有首页、产品介绍、联系我们三个页面，风格简洁大气。
> 【范围】这次只做这三个页面，先不做登录、不做后台、不做在线聊天。
> 【验收】三个页面在电脑和手机上都能正常打开，产品介绍页能放下 6 张图，页脚有公司名和电话。

就这四句，Agent 拿到就能开工，不用回头问你「几个页面？要登录吗？手机上要看吗？」。

## 三种最常见的需求，各自怎么套

### 1. 从零做一个东西（网页 / 网站 / 工具）

套模板 + 多给一句「参考」：

> 【背景】【目标】【范围】【验收】…… 另外风格参考淘宝首页那种感觉，或者我给你看张截图。

**加一张参考截图或一个参考链接，胜过你形容十句。** 这是最省力的「说清楚」。

### 2. 改一个已有的东西（改颜色 / 改文案 / 加按钮）

用「**当前 → 想要**」句式，别只说「改一下」：

> ❌ 「把首页改一下」
> ✅ 「首页顶部的标题现在是黑色小字，帮我改成红色、30px、居中；再把『联系我们』按钮从灰色改成蓝色圆角。」

把「现在是什么」和「要变成什么」都说了，Agent 零猜测。

### 3. 修一个报错（出 bug 了）

用「**做了啥 → 报了啥 → 想要啥**」：

> ❌ 「报错了，帮我修」
> ✅ 「我运行了 npm run dev，终端报了 `port 3000 already in use`。我想让它在 3000 端口正常跑起来，或者换个能用的端口，告诉我换了哪个。」

**把报错原文整段复制给 Agent**，别自己转述。报错信息就是它看病的化验单。

## 说清需求前的「出门前自检」清单

发需求前，问自己五句，能答上就发，答不上就补：

- [ ] **给谁用？** （自己 / 老板 / 客户 / 所有人）
- [ ] **做完长什么样？** 能不能用一句话描述画面
- [ ] **这次到底做多少？** 有没有说「先不做 xxx」
- [ ] **怎么算完成？** 能不能说出「我打开看到 xxx，点 xxx 会有 xxx」
- [ ] **有没有参考？** 截图 / 链接 / 类似产品，有就给

五句都能答上，你的需求就已经是「好需求」了。

## Agent 反问你，是好事，别嫌烦

你发完需求，Agent 很可能会追问：

> 「这个页面要几栏？」「手机上的布局要一样的还是可以简化？」「按钮点了之后要跳转还是弹窗？」

**这是它在帮你把需求补完整，不是它没听懂。** 它问得越细，做出来越对。

三个应对方式：

| 情况 | 你怎么回 |
|---|---|
| 你答得上来 | 直接回答，越具体越好 |
| 你答不上来 | 「这块我还没想好，你按常见的做法先做一版，我看了再改」 |
| 你觉得它想多了 | 「先别管这个，先做核心的 xxx」 |

## 一张「需求说明书」完整范例（直接照抄改）

```text
【背景】
我想给我们的摄影工作室做一个预约页面，给来咨询的客户用，
因为现在客户都在微信里问档期，很乱。

【目标】
一个网页：客户能看到可预约的时间段，选一个，填名字和电话，提交。
风格要干净、偏文艺，符合摄影工作室的调性。

【范围】
这次只做预约这一个页面。
先不做：支付、会员系统、后台管理、多语言。

【验收】
1. 我在电脑和手机上打开，页面都正常、不错位。
2. 选一个时间段，填名字和电话，点提交，能提示「预约成功」。
3. 提交的内容能被记录到一个地方（先存下来就行，不用做后台页面）。
4. 页面顶部有工作室名字和 Logo 位置。

【参考】
类似这种风格（附一张截图 / 一个链接）。
```

这一段发出去，Agent 基本能一次性交付，剩下的小调整都是「再改改」级别。

---

## 一句话总结

> **说不清需求，是把成本从「开头多花 3 分钟说清楚」，转移成「后面来回改 30 分钟」。**
> 先花 3 分钟，把背景、目标、范围、验收四句填了，再发给 Agent。
