# 🎵 vibe coding 主线地图

> **如果你已经会用 AI 写代码，但总感觉「差点意思」——这四篇是给你的。**
>
> 你缺的不是工具，是**节奏感**：一轮做多少、怎么验收、什么时候该停。
> 这四篇把这套节奏讲透。全部读完约 40 分钟。

## 四篇主线

```
V1  什么是 vibe coding
     ↓  先搞清楚「跟让 AI 写代码差在哪」
V2  一轮该做多小
     ↓  学会把一轮切到「一眼能判断对错」
V3  不会写代码，怎么验收
     ↓  拿到三个信号 + 一张红线表
V4  人机分工与长期不失控
     ↓  三道防线，项目能一直做下去
```

| | 章节 | 花多久 | 核心收获 |
|:--:|---|:---:|---|
| **V1** | [什么是 vibe coding](./vibe-coding-what.md) | 8 分钟 | 它和「让 AI 写代码」的根本区别；为什么小步更重要 |
| **V2** | [一轮该做多小？](./vibe-coding-loop.md) | 10 分钟 | 粒度参照表、每轮四步、**每轮必问的三句话** |
| **V3** | [不会写代码，怎么验收？](./vibe-coding-review.md) | 12 分钟 | 三个信号、**红线信号表**、纠偏三招 |
| **V4** | [人机分工与长期不失控](./vibe-coding-boundary.md) | 10 分钟 | 分工表、**三条红线**、上下文管理四招 |

## 这条主线的一句话总结

> **vibe coding 不是「随便让 AI 写」，是「把判断力用在刀刃上」。**
>
> 你管方向和验收，AI 管实现；每一轮小到你能一眼判断；做完真的动手试一遍；项目变大就收口、落文件、存档。
